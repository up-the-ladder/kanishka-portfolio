Selected projects

Software engineering

Relay

Distributed job execution platform in Go.

Clients submit asynchronous jobs over gRPC, and PostgreSQL holds durable job state and coordinates concurrency-safe claiming across workers. Relay treats failure as a normal operating condition: leases, worker heartbeats, failure detection, retries with exponential backoff, and idempotent execution let abandoned work be recovered safely. The substance of the project is in transactional ownership, races between competing claimants, graceful shutdown, and recovery after a process dies mid-job.

Go · gRPC · PostgreSQL · Redis · Docker · Kubernetes

  • GitHub

IndexForge

Search engine written from scratch in C++20.

Ingests documents, builds an inverted index and posting lists, maintains corpus statistics, retrieves candidates, ranks with BM25, and does heap-based top-k selection. It is being extended to persist indexes to disk, parallelize indexing across worker threads, and serve concurrent queries safely. Rather than adding optimizations speculatively, it establishes reproducible baselines, profiles real workloads, and then attacks measured bottlenecks in synchronization, memory layout, caching, and retrieval.

C++20 · CMake · multithreading · BM25 · GoogleTest

  • GitHub

VaultFS

Cloud file-storage backend built around correctness under concurrency.

A Java and Spring Boot storage service designed around chunked, resumable uploads with parallel chunk processing, SHA-256 integrity checks, file versioning, and content-based deduplication, with PostgreSQL holding authoritative metadata separately from object contents. Upload sessions, transactional state changes, idempotent retries, and optimistic concurrency control handle interrupted transfers and competing clients. It grows incrementally from a streaming local-storage baseline, with Redis introduced only where metadata caching measurably helps.

Java · Spring Boot · PostgreSQL · Redis

Bubble Rush Grand Prix

Arcade game with no game engine. Physics, collision, rendering, and audio are all written by hand.

The central constraint was running a 60 fps simulation inside React without triggering continuous re-renders: all mutable game state lives in one useRef object the loop mutates directly, while React state receives display-only updates once per frame. Collision uses circle-vs-rectangle geometry for bubbles and directional-guarded AABB for traffic, and the spawn system tracks per-frame lane occupancy to guarantee at most three traffic cars and always one free lane. Sound is synthesised entirely with the Web Audio API.

Machine learning & ML systems

Multimodal Video Search & Ranking Engine

Natural-language search inside video.

Segments and indexes video across four modalities: spoken transcripts from Whisper, visual frames from OpenCLIP, on-screen OCR text, and generated captions from BLIP. Candidate segments are retrieved by sparse BM25 and dense FAISS search, then multimodal fusion and optional cross-encoder reranking form a two-stage ranking pipeline. The architecture is argued experimentally rather than by stacking models: transcript-only, visual, sparse, dense, hybrid, and reranked systems are compared under controlled retrieval evaluation on Recall@K, MRR, NDCG, and latency.

Python · PyTorch · Whisper · OpenCLIP · BLIP · FAISS · BM25 · cross-encoders

  • GitHub

Personalized Search Ranking Engine

Learning-to-rank reranker over video search results.

Reranks results on both query relevance and individual user behaviour, building ranking-time features from watch history, engagement, creator affinity, content signals, and semantic relevance, then scoring with LambdaMART via LightGBM Ranker. It covers the whole ranking lifecycle: label construction, negative sampling, leakage-aware dataset splitting, ranking-specific offline evaluation on NDCG@K, MRR, MAP and Recall@K, controlled feature ablations, and error analysis. Serving runs on FastAPI with PostgreSQL for persistent data and Redis where low-latency feature retrieval is justified, with offline training and online inference kept explicitly separate so features stay consistent.

Python · LightGBM · LambdaMART · FastAPI · PostgreSQL · Redis · Docker

Academic & research work

Adaptive Inference Scheduling for Diffusion-Based MRI Reconstruction

Cutting denoising cost in conditional diffusion reconstruction.

Trains a conditional diffusion model to reconstruct brain MRI from undersampled k-space, then reduces inference cost with an adaptive early-stopping controller. Instead of running a fixed number of denoising steps for every image, the controller monitors three per-sample convergence signals (predicted-noise magnitude, x0-prediction stability, and measured k-space consistency) and halts once a reconstruction stabilizes, with a patience mechanism guarding against premature stops. Built in PyTorch with DDIM sampling and data-consistency projection, and evaluated on Calgary-Campinas at 4× and 8× acceleration: roughly 25% fewer denoising steps with higher PSNR and lower NMSE than fixed 100-step sampling, at a modest SSIM cost.

PyTorch · diffusion models · DDIM · Calgary-Campinas

Sentiment-Aware Bitcoin Volatility Forecasting

Do behavioural and cross-market signals improve short-horizon crypto risk forecasts?

Predicts next-hour realized Bitcoin volatility from a 72-hour history, combining BTC and ETH market data with S&P 500, gold, Twitter activity, Fear & Greed signals, cross-asset correlations, and temporal features. A five-block N-BEATS model performs iterative residual decomposition, and a custom Huber, jump and trend loss handles heavy-tailed observations, abrupt volatility transitions, and long-term drift. Benchmarked against LSTM, CNN, Transformer, and Temporal Fusion Transformer baselines under a chronological evaluation protocol. N-BEATS reached a validation MAE of 0.2897, with loss ablations supporting the full hybrid objective.

Python · PyTorch · N-BEATS · time-series forecasting
